# Grok upstream 补丁边界

## 目录归属

- `runtime/`：shengtu 自有适配层，遵循 Python 单文件有效行数不超过 300 行。
- `upstream/`：从 `gptGrok2api-main` 裁剪的 vendored 快照，不做纯格式、纯命名或仅为满足行数限制的批量重构。

截至 2026-08-03，`upstream/` 有 63 个 Python 文件超过 300 有效行。该数字是历史基线，不代表允许继续增长。

## 允许的本地补丁

只有以下情况可直接修改 `upstream/`：

1. 可复现的生产 bug 或安全问题。
2. shengtu 与 upstream 的接口适配缺口。
3. 上游尚未发布修复，而本地必须先恢复功能。

每个补丁必须同时满足：

- 改动范围只覆盖根因，不顺带整理相邻代码。
- 在同模块补定向测试；无可测边界时不得修改。
- 修改前记录上游文件和行为，修改后运行对应 pytest。
- 已超限文件不得因本地补丁增加有效行；新增逻辑优先放入小型适配模块。

## 禁止事项

- 不把 63 个历史大文件一次性机械拆分。
- 不批量替换宽泛 `except Exception`；必须先证明具体异常被错误吞掉。
- 不在 upstream 内复制 shengtu 的鉴权、配置或 HTTP 适配逻辑。
- 不删除未知用途分支来换取行数下降。

## 同步策略

后续更新 upstream 时，先运行完整 Python 测试，再逐项重放仍有必要的本地补丁。已被上游覆盖的补丁直接删除，不保留双路径兼容。
