# Cloudflare R2 图片媒体存储

## 数据边界

- R2 私有桶：保存原图和缩略图对象。
- SQL `media_assets`：保存用户归属、公开状态、对象键、校验值、分页游标和重试状态。
- `data/media-spool`：保存尚未成功上传的对象；成功并校验后自动移除。
- `/images/...` 与 `/image-thumbnails/...`：保持原有站内地址，鉴权通过后返回短期预签名地址。
- 图片库下载使用站内 `/images/...?download=1`，R2 签名会携带附件响应头；浏览器不需要跨域 `fetch`，常规查看和下载不依赖 Bucket CORS。

R2 模式只支持 SQLite、PostgreSQL 或 MySQL 存储后端，不支持 JSON 后端。

## 首次迁移

1. 保持 `CHATGPT2API_MEDIA_STORAGE_PROVIDER=local`。
2. 在「设置 → 媒体存储」填写并保存 R2 凭据。
3. 执行“测试连接”。
4. 执行“迁移旧图片”，等待进度结束；重复执行会跳过已迁移记录。
5. 再将存储切换为 `r2`，保存后重启主应用。
6. 验证本人图片、管理员全部图片、公开图片、原图和缩略图访问。

## CORS 边界

本站图片库的查看和下载链路不要求 R2 Bucket 配置 CORS。只有其它域名中的前端代码需要直接 `fetch` R2 签名地址时，才应在 Bucket 中允许对应的明确 Origin 和 `GET`/`HEAD` 方法；不要为此使用带凭据的任意来源规则。

迁移只读本地旧图并上传，不删除本地图片。迁移期间若仍有新图片写入本地，应在切换前再执行一次幂等迁移。

## 故障与回滚

- R2 短时故障：新图片进入 `pending`，由后台每分钟重试；缓冲存在时仍可读取。
- 连接或权限异常：设置页健康检查会返回明确错误，不回显 Secret Access Key。
- 回滚：将 provider 改回 `local` 并重启；旧图片仍在本地。切换前不要清理本地回滚副本。
- Secret、数据库和 `media-spool` 必须随生产数据一起纳入备份策略。
