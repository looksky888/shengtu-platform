## 版本与边界

本版本从本地 4.5 独立复制，仅调整 ChatGPT 网页号池链路。
4.5、线上服务器、用户数据库、积分/充值/退款规则和中转站代码未修改。
没有数据库迁移。回滚为使用 4.5 镜像与原配置；不要回滚或覆盖用户数据库。

## 数据流

1. Go 按当前已选账号解析专用代理与 IANA 时区；未配置时继承系统代理和默认时区。
2. Go 向私有 solver POST /v1/context，只传该代理、时区，不传账号 token、Cookie 或 prompt。
3. solver 按“完整代理 URL + 时区”隔离并复用匿名 Chromium context，取得 25 字段 p、UA、client hints、时区和页上下文 ID。
4. Go 验证 p/UA/locale、IANA 时区及偏移、代理配置摘要一致；上游请求使用同一账号代理和浏览器元数据。
5. Go POST chat-requirements/prepare，提交 p；在同一配置上求 PoW。
6. 有 Turnstile 时将 context_id、p、dx 和完整 prepare challenge 发给 solver；不发送账号 token、Cookie 或用户 prompt。solver 优先动态发现并调用网页自身 Turnstile 模块，失败才回退本地 VM。
7. finalize 总是提交 prepare_token、proofofwork、turnstile 三字段；仅接受最终 token，并只清理 finalize 写入的受限 `oai-sc` cookie。
8. prepare 与正式 conversation 使用同一 turn trace、`client-created-root` 和当前 picture_v2 消息结构。`gpt-image-2.5` 规范化为 flare，显式 flare/sunburst 原样透传；旧 `gpt-image-2` 配置映射保持不变。

上下文两分钟内有效，已签发 p 只能用于一次挑战；页面重建后旧上下文拒绝。
solver 缺失、失败、参数非法、上下文过期均明确报错，不降级到旧 Go 模拟器。
相同代理和时区复用一个匿名页面并串行执行挑战；不同账号出口使用隔离 context，最多保留 32 个活跃 context，空闲 30 分钟回收。API 最多 8 个排队请求；这不是修改账号池生图并发。

## 精确 404 处理

仅 POST /backend-api/f/conversation 实际发出的 model=auto，
HTTP 404、完整 JSON 顶层 detail 字符串严格等于 Model not found 才标记。
prepare、模型列表、上传/下载、SSE 中的文本、其他状态码和其他模型均不适用。

在原每张最多 4 次尝试内换号，失败账号进程内冷却 10 分钟，原子释放占用；
不写账号状态/额度/失败计数，不扣代理健康分，不动用户积分。
剩余尝试固定实际 auto 模型，不因换号轮数切到 FallbackModels。
其他在途任务成功不会清除此冷却；进程重启后本地冷却自然消失。
原有退款/账务流程维持不变，真实计费验收须另核对。

## 部署配置（本次未部署）

普通、local、WARP Compose 都包含 sentinel-solver；不发布 solver 主机端口。
必须配置 CHATGPT2API_SENTINEL_SOLVER_KEY（随机且至少 32 字符），
以及 SENTINEL_SOLVER_TIMEZONE（系统默认出口对应的 IANA 时区）。
Compose 内主服务 URL 为 http://sentinel-solver:8080；账号未配置专用出口时二者共用 CHATGPT2API_PROXY。
账号可在号池编辑框配置完整专用代理和时区，主请求与 solver 会在一次尝试内冻结并共同使用。
配置摘要一致只证明完整代理 URL 一致；会自行轮换 IP 的供应商仍需现场验证实际出口和时区。

solver 非 root、启用 Chromium sandbox；768 MiB 内存、1 CPU、256 PID、
128 MiB /dev/shm，日志最多 2×10 MiB，不挂用户数据卷。
Linux 宿主机需支持 Chromium 用户命名空间 sandbox；本地 Windows 测试不代表
目标 Docker 安全策略已兼容。启动失败应检查策略，不使用 privileged/--no-sandbox 兜底。

app 只依赖 solver 已启动，不以匿名网页可达性阻塞整个站点：
solver 不可用时本地 ChatGPT 请求报错，中转站仍由独立执行链路处理。
/health 返回匿名页面就绪状态，503 不等于主站需重启。

部署前先校验备份和资源余量，在本地/构建机打包；生产主机不现场执行大规模构建。
主服务和 solver 应同批发布，避免主服务指向缺失端点。

## 验证分层

- Go 契约测试：25 字段、FNV 独立 JavaScript 测试向量、取消、字段一致、prepare/finalize、
  禁止重定向泄钥；正负 404 案例；冷却与重试总预算。
- Python HTTP 测试：鉴权、未知字段、超长输入、上下文过期、错误不回显挑战内容。
- 真实 Chromium 离线测试：合成网页上读取真实 UA/时区，验证网页 Turnstile 模块优先、VM 回退与重复 p 拒绝。
  此测试不访问真实 ChatGPT，不证明上游接受挑战。
- 前端无变更，校验原 dist 与源码一致；全量 Go 测试包含账务与渠道隔离现有回归。

真实验收工具：scripts/verify-image-output.py，依赖 httpx 和 Pillow。
显式使用 --confirm-charge，交互输入测试 API key，不将 key 写命令行或文件。
工具分别请求 /v1/images/generations 和 /v1/images/edits，读取结果字节后先 verify 再 load，
输出耗时、格式、宽高、字节数和 SHA256，不输出签名下载 URL 或密钥。
返回 200、SSE 结束、存在图片 URL 都不足以判定成功。

示例（在配置好测试环境后执行，可能消耗测试积分）：

```text
python scripts/verify-image-output.py --base-url http://127.0.0.1:3004 --mode both --confirm-charge
```
