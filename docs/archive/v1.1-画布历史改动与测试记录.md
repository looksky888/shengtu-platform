时间：2026-05-21

## 本轮目标
- 画布配置节点一次生成多张图片时，将同一轮结果组成一个批次。
- 默认显示第一张作为批次主节点，支持展开/折叠其余图片节点，降低画布拥挤度。

## 追加修复：读取生成结果 404
- 问题现象：画布提交生成后，显示“读取生成结果失败（404）”，导致图片节点没有真正加入画布，因此看不到图片节点悬浮按钮或右键菜单里的批次折叠入口。
- 根因：任务返回的图片 `url` 是外部域名（例如 `https://www.shengtu.xyz/images/...`），本地画布直接去抓这个地址会失败。
- 修复方式：
  - `web/src/features/canvas/adapters/generation.ts` 优先把任务结果 URL 转成同源 `/images/...` 再读取。
  - 本地测试缓存 `.env` 的 `CHATGPT2API_BASE_URL` 已改为 `http://127.0.0.1:8000`，避免新任务继续写出外部域名图片链接。
- 部署提醒：如果后续发布到服务器，需要把 `CHATGPT2API_BASE_URL` 改回正式域名或服务器外部访问地址。

## 追加修复：多图生成长期 running
时间：2026-05-21

### 现象
- 画布配置节点设置生成 3 张后，任务长时间显示处理中。
- 数据库中最近任务为：`status=running`、`count=3`、`data=[]`、`error=`，前端只是持续轮询 `/api/creation-tasks`。

### 原因
- 当前二开版本此前把多图作为一个任务提交：`count=n`。
- 当上游单个多图任务卡住时，整批图片都无法返回，画布也没有可追加的图片节点。

### 参考原项目策略
- 原项目 `infinite-canvas-0.0.5` 在多图时会创建批次节点，然后对每张图单独请求：
  - `requestGeneration({ ...generationConfig, count: "1" }, ...)`
  - 或 `requestEdit({ ...generationConfig, count: "1" }, ...)`
  - 外层用 `Promise.all(targetIds.map(...))` 并行处理。
- 也就是“用户选择 3 张”实际拆成 3 个独立的 `count=1` 请求。

### 本轮修复
- `web/src/features/canvas/store/use-canvas-generation-store.ts`
  - 将单个 `task-0 / count=n` 改为多个任务：`task-0...task-n-1`。
  - 每个任务提交 `count: 1`。
  - 轮询、统计、终止逻辑继续按 `taskIds[]` 处理。
- 好处：
  - 某一张卡住/失败不会直接拖死整批。
  - 成功的图片可以先进入画布。
  - 终止时会按多个子任务逐个取消。

### 验证
- `npm run build`：通过。
- `go build -tags=embed ...`：通过。
- 本地服务已重启：`http://127.0.0.1:8000`。

## 追加修复：拆分任务后批次折叠入口不显示
时间：2026-05-21

### 现象
- 配置节点设置生成 3 张，最终出现 3 个图片结果，但没有“折叠/展开”入口。

### 原因
- 多图已改为多个 `count=1` 子任务。
- 旧批次逻辑只在一次 `appendGeneratedImages(...)` 同时收到多张图时创建批次。
- 分批返回时每张图都被当成独立输出节点，未挂到同一个批次 root。

### 修复
- `web/src/features/canvas/store/use-canvas-store.ts`
  - `appendGeneratedImages(...)` 增加 `batchRootId` / `batchSize` 参数。
  - 第一张结果在 `batchSize > 1` 时创建批次 root。
  - 后续结果自动作为 child 追加到 root，并更新 `batchChildIds`。
- `web/src/features/canvas/store/use-canvas-generation-store.ts`
  - 追加图片时传入当前运行批次的 root 信息。
  - 同一轮多个子任务同时返回时，也会复用刚创建的 root。

### 验证
- `npm run build`：通过。
- `go build -tags=embed ...`：通过。
- 本地服务已重启：`http://127.0.0.1:8000`。

## 追加修复：批次 rootId 受 React 异步状态影响
时间：2026-05-21

### 现象
- 用户重新生成 3 张后，画布 JSON 中 3 张图片仍然没有 `batchRootId` / `batchChildIds` / `imageBatchExpanded` 字段。

### 进一步原因
- 拆分任务后，每张图片独立返回。
- 之前依赖 `appendGeneratedImages(...)` 同步返回第一张图片节点 ID 作为 rootId。
- React 状态更新是异步/队列式，返回时 rootId 不稳定，导致后续图片没有挂入批次。

### 修复
- 新增 `batchGroupId`：同一轮多图生成的所有子任务共享同一个批次组 ID。
- `appendGeneratedImages(...)` 在没有明确 rootId 时，会通过 `batchGroupId` 在当前画布文档中查找同组 root。
- 第一张图创建 root，后续图即使不知道 rootId，也会自动加入同组 root 的 `batchChildIds`。

### 验证
- `npm run build`：通过。
- `go build -tags=embed ...`：通过。
- 本地服务已重启：`http://127.0.0.1:8000`。
